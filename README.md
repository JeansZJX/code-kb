# code-kb

用于多人协作项目的 Codex 技能：开发前查团队规范和已有功能，开发后写简短、独立的变更记录，帮助复用代码并减少知识文档的共同编辑。

适用于前端、后端、技术策划的脚本和配置工具，以及技术美术的编辑器工具、Shader、资源处理流程。本仓库只分享技能说明，不包含任何业务项目的源码、协议、知识记录或团队规范。

## 安装

下载本仓库 ZIP 并解压，把 `skills/code-kb` 整个文件夹复制到以下任一位置：

- 项目内的 `.agents/skills/code-kb`。
- 当前用户自己的全局技能目录下的 `code-kb` 文件夹。

安装后开始新的 Codex 会话，确认能选择 `code-kb`。技能运行不依赖 Node.js、npm、SVN 命令行或其他技能；SVN 更新与提交可继续使用团队现有客户端。

可选安装脚本需要 Node.js。在项目根执行，升级时使用 `--replace`：

```powershell
$packageDir = Read-Host 'code-kb 的解压目录'
node (Join-Path $packageDir 'scripts/install.mjs') --project-root . --replace
```

## 建立项目知识库

在项目根保存 `code-kb.project.json`。例如：

```json
{
  "knowledge_base": ".code-kb"
}
```

知识库只需要下面的目录，由负责人按实际项目建立；已有知识库保留内容，逐步整理即可。

```text
.code-kb/
├── README.md
├── rules/
├── features/<来源ID>/<功能ID>.md
└── changes/<日期>-<任务>-<UUID>.md
```

知识库的 `README.md` 写明维护者，并用简单来源表登记代码或文档根、状态与适用规范。所有路径相对项目根。主干和分支分别登记，不把分支代码事实当成主干事实。模板见 [记录说明](skills/code-kb/references/records.md)。

在项目自己的 `AGENTS.md` 加入：

```markdown
代码、脚本、配置工具和资源流程任务使用 code-kb 技能。
按 code-kb.project.json 定位知识库，先查规范、相关功能卡、变更单与当前代码，再开发。
每个任务新增独立变更单；功能卡由维护者协调汇总，规则变更先提案。
项目知识与代码留在本项目中，不加入技能分发仓库。
```

## 使用

从自己的项目根打开 Codex，可按任务调用：

```text
$code-kb 整理现有背包刷新功能，核验公共入口和关键调用，建立简短功能卡；只整理这次指定的范围。
```

```text
$code-kb 实现采集完成后的背包刷新，先查规范和已有实现，优先复用；验证后新增本任务的变更单。
```

首次整理由负责人组织，从常用公共入口开始，不导出全部类和函数。日常开发先搜索功能卡，同时查对应变更单与源码；未找到记录时继续搜源码。记录只保留职责、入口、必要调用方式和约束，不建立全库候选索引或完整引用图。

## 多人协作

成员开工与提交前同步相关代码和知识库。默认每个任务只新增有 UUID 的独立变更单，不改别人的卡片；维护者根据单据和当前源码汇总。规范保持稳定，修改先写独立提案。历史通过变更单与 SVN 日志追溯，不维护共享总索引或 CHANGELOG。

独立记录能减少知识文档冲突。同一脚本仍需协调修改范围，优先使用各自的 SVN 工作副本；同一物理目录里不要并行修改相同文件。发生冲突时保留双方有效修改，核对合并后的源码和调用。在同一 SVN 仓库时，相关代码和变更单尽量同次提交。

新版通过 Codex 阅读、检索和维护 Markdown，不提供自动 SVN 提交、并发锁或自动检查器。完整工作约定见 [SKILL.md](skills/code-kb/SKILL.md)。升级前核对团队使用的技能版本，技能升级与项目知识更新分别维护。
